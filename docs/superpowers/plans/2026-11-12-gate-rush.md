# Gate Rush Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Gate Rush, an original 3D crowd-runner web game installable on an iPhone Home Screen.

**Architecture:** A pure, browser-free simulation (`rules.js`, `levelgen.js`, `sim.js`) holds all game state and emits events. `render.js` draws that state with Three.js instanced meshes; `audio.js` and `ui.js` react to events. `main.js` runs the loop and screen flow.

**Tech Stack:** Plain HTML/CSS/JavaScript ES modules, Three.js (vendored), Web Audio API, Node built-in test runner (`node --test`). No build step, no runtime dependencies beyond Three.js.

**Spec:** `docs/superpowers/specs/2026-11-12-gate-rush-design.md`

## Global Constraints

- Original game: no names, characters, art, levels or look from any existing title.
- No build step; every file is served as written. Three.js is vendored in `vendor/`, not loaded from a CDN.
- No external art or audio files. Shapes are Three.js primitives; sounds are synthesised.
- Portrait, one-thumb control. Only input during a run is horizontal drag.
- Level run time 60–90 seconds before the boss.
- At most 300 soldiers drawn; army count itself is capped at 99999.
- `rules.js`, `levelgen.js`, `sim.js`, `save.js` must not import Three.js or touch `window`/`document`.
- Sound effects only, no music. Audio starts on first tap. Mute setting persists.
- Nothing is published to the internet without the user's explicit go-ahead.
- Commit after every task. End commit messages with `Co-Authored-By: Claude Fable 5.2 <noreply@anthropic.com>`.

## Review Focus

1. **Frame-time spike** (tab switched away and back, slow frame): the army must not skip through a gate, enemy or the boss trigger. Expect `dt` clamped and sub-stepped. Test in Task 3.
2. **Corrupt or old saved data** in `localStorage`: expect a fresh game, never a crash or `NaN` coins. Test in Task 5.
3. **Runaway numbers** from repeated multiply gates: expect army capped at 99999, no `NaN`/`Infinity`, and compact display ("12.3K"). Test in Task 1.
4. **Finger lifted, second finger, or drag starting off-centre:** expect steering to be relative to where the drag began, with no jump. Test in Task 6.
5. **Rotation, resize, and iPhone notch/home-bar:** expect the canvas to refill the screen and all buttons to sit inside safe areas. Manual check in Task 9.

```js
export function generateLevel(n) // n >= 1 ->
// {
//   number, length,              // length = 480 + 12 * Math.min(n, 20)  (60–90 s at RUN_SPEED)
//   theme,                       // Math.floor((n - 1) / 5) % 4
//   items: [                     // sorted by z ascending, all z in [40, length - 30]
//     { type:'gates',  z, left:{op,value}, right:{op,value} },   // left covers x < 0, right x >= 0
//     { type:'squad',  z, x, count, hp },                        // hp is per enemy
//     { type:'barrel', z, x, hp, coins },
//     { type:'crate',  z, x, weapon, hp },
//   ],
//   boss: { hp, dps, big }       // dps = soldiers removed per second in contact; big = n % 5 === 0
// }
```

Rules the generator must follow:
- Deterministic: PRNG is mulberry32 seeded with `n`.
- A row every 36–44 units. Row types cycle with random variation, but: first row is always a gates row; at least 6 gates rows per level; no two crates in one level before level 4, at most two after; crates only offer weapons from `unlockedWeapons(n)` other than `'rifle'`, so level 1 has no crates.
- Gates: at least one side satisfies `gateIsGood`. About 1 pair in 4 has a trap side. Add values scale `5 + n*2 … 15 + n*4`; mul values are 2 or 3 (3 only from level 3); sub values are at most a third of the add scale; div value is 2.
- Squad `count` 3–6 at level 1 rising to 10–25 by level 20; enemy `hp = 10 + 3n`.
- Barrel `hp = 60 + 40n` (±25%), `coins = 5 + n`.
- Crate `hp = 80 + 30n`.
- Boss `hp = Math.round(1500 * 1.22 ** (n - 1) * (big ? 1.6 : 1))`, `dps = 1 + Math.floor(n / 4)`.

### Task 3: Simulation — the run

**Files:**
- Create: `src/sim.js`
- Test: `tests/sim.test.js`

**Interfaces:**
- Consumes: everything exported by `rules.js`; `generateLevel` from `levelgen.js`.
- Produces:

```js
export function createRun(levelNumber, save) // ->
// { level, phase:'run', t:0, x:0, z:0, army, weapon:'rifle', coins:0, kills:0,
//   fireTimer:0, items:[...level.items each with alive:true and current hp],
//   enemies:[{x,z,hp,alive}], bullets:[{x,z,vx,vz,damage,kind,ttl}],
//   boss:null, events:[] }
export function stepRun(run, dt, steer, save) // steer in [-1, 1]; mutates run; appends to run.events
export const MAX_STEP = 1 / 30;
```

Behaviour:
- `stepRun` clamps `dt` to 0.25 then advances in sub-steps of at most `MAX_STEP`.
- `run.x` moves toward `steer * ROAD_HALF` at up to 14 units/s, clamped to `±(ROAD_HALF - 0.5)`.
- In phase `'run'`, `run.z += RUN_SPEED * step`.
- Gates: when z crosses a gates item, apply the side matching `run.x`; mark it dead; event `{type:'gate', good, label, army}`.
- Squads: activate when within 45 units ahead, spawning `count` entries into `run.enemies` around the squad's x; enemies advance toward the army at 3 units/s and drift toward `run.x`. An enemy within 1 unit of the army front removes one soldier and dies (`{type:'soldierLost'}`).
- Barrels/crates: contact with an alive one (|dx| < 1.2 when z crosses it) removes `Math.ceil(hp / 40)` soldiers and destroys it (`{type:'crash'}`).
- Firing: every `fireInterval`, find the nearest alive target (enemy, barrel, crate, boss) within the weapon's range and roughly ahead (|dx| ≤ 3, or any x for the boss). If one exists, spawn bullets carrying `volleyDamage` split across them: `bullet` → 1 bullet; `spread` → 5 bullets fanned ±20°; `rocket` → 1 bullet that on hit damages everything within `splash`; `beam` → no bullet, instantly damages every target in a 1.5-wide column up to range. Event `{type:'shot', weapon}`.
- Bullets travel at 60 units/s, hit the first target within 0.8 units, and expire by `ttl`.
- Deaths: enemy → `kills++`, `coins += 1`, `{type:'kill', x, z}`; barrel → `coins += item.coins`, `{type:'barrelDown', x, z, coins}`; crate → `run.weapon = item.weapon`, `{type:'weapon', weapon}`. Any hit → `{type:'hit', x, z, damage}`.
- If `run.army <= 0` → `phase = 'lost'`, event `{type:'lost'}`, and no further changes on later steps.
- When `run.z >= level.length` → phase `'boss'` (boss logic is Task 4; here just set the phase and `{type:'bossStart'}`).

  - Steering: after 2 s of `steer = 1`, `run.x === ROAD_HALF - 0.5`.
  - Gate left `+10`, right `×2`, army 5: with `x < 0` crossing gives 15; with `x >= 0` gives 10; exactly one `gate` event.
  - **Frame spike:** a single `stepRun(run, 5, 0, {})` with a gate at z=1 still applies the gate, and `run.z <= RUN_SPEED * 0.25 + 1e-9`.

  - A barrel with hp 100000 at z=6 on the army's x costs `Math.ceil(hp/40)` soldiers capped at the army → phase `'lost'`; a further `stepRun` leaves `z` unchanged.
  - A crate with hp 1 offering `'mg'` sets `run.weapon === 'mg'` and emits a `weapon` event.
  - With `run.weapon = 'rocket'` and three enemies 1 unit apart at hp 1, one volley kills all three.
